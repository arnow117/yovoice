# REQ-002 — Mac App 声纹交互验证页面

## 原始请求、方向来源与问题

用户原始请求：**「加个页面吧，整体还是用 yovoice 原有 Mac App 来验证最好的。」**

前文已确认要交互式完成声纹登记、识别、档案管理及绑定音色后的生成。REQ-001 / FEAT-001 已完成非实时声纹 CLI / HTTP 原型的源码交接；本需求在原 yovoice Mac App 中提供对应入口，以真实桌面调用验证这条链路。一个可交付结果是：操作者在原 App 内选文件或录音、建立档案、识别另一段录音、查看和删除档案，并显式选择绑定档案生成。

长期产品目标文档：`none`。本次方向由用户请求及已接受的 `.sdlc-v1/context/REQ-001.product.md` 提供；`.sdlc-v1/project.md`、`AGENTS.md`、现有导航/录音/生成源码及 `docs/usage.md` 提供兼容性与体验约束，不作为新的产品战略。核对源码快照为 `83c1366b53d8ce0c5ff80fe0a80714cfde96c090`，开发分支为 `codex/speaker-validation-ui`；状态文件显示 REQ-001 / FEAT-001 均为 `released`。

当前 App 没有声纹页面。原导航、声音库、录音及试听能力已经存在，Swift 宿主已处理可信页面的麦克风授权；现有录音保存和声音导入会创建声音库素材，不能让识别查询因复用这些交互而变成持久化声音。现有声纹特征独立于普通 State，新增页面须延续这个隐私边界。

## 用户、期望结果与成功指标

目标用户是当前 Mac 上的本地操作者和开发验证者，使用同一 App 数据目录中的档案和声音库。显示标签只表示操作者登记的声音档案，不证明现实身份；不增加账号、多租户或声纹认证。

| 结果 | 当前基线 | 本次目标与观测方式 |
|---|---|---|
| 原 App 中完成操作 | 声纹能力只能由 CLI / HTTP 调用 | 从原导航进入声纹页面，在 App 内完成登记、识别、列表刷新、删除和已绑定档案的显式生成；记录实际 App 旅程 |
| 判断结果可理解 | 无桌面结果呈现 | 区分 matched / unknown / ambiguous 与输入、配置、执行错误；展示原始分数、有限候选及当前 T/M，不把相似度显示为准确率或概率 |
| 数据不意外增加或泄露 | 查询服务只读，特征不进入普通 State | 查询前后声音库、档案及绑定不变；公开页面数据、State 和错误反馈不含 embedding 或内部存储/执行路径 |
| 真实桌面链路可复现 | 已有 CLI / HTTP 实模识别小样本结果，尚无本页面证据 | 在构建出的原 Mac App 中，用固定模型、参数及独立查询录音验证两名已登记者分别正确 matched，一名未登记者不被 matched；保留样本级结果、耗时和被测版本 |
| 依赖缺失可恢复 | 识别需本地配置，TTS 模型可能未准备 | 缺配置、麦克风拒绝、绑定失效或 TTS 不可用时，页面说明具体原因和下一步；列表管理及其他已满足条件的操作仍可使用，不自动下载模型 |

有限样本只说明对应输入的真实结果，不能推导人群准确率、防伪能力或生产可用性。功能验收、真实识别、麦克风实机录制和 TTS 人工听测分别报告，不能相互替代。

首次本地页面交付后观察 7 天，负责人为当前用户与开发者，人工记录误匹配、拒绝、时延、录音失败、失效绑定及无法恢复的状态。没有生产遥测；证据随被测版本保存。反馈若改变产品行为或范围，另建依赖 REQ-002 的 Requirement，不回写已完成的 REQ-001；本次不创建自动监控。

## 范围与产品取舍

范围内：

- 原 App 的清晰「声纹」入口及页面，复用当前导航、Astryx 设计系统、语言/主题、反馈和播放器体验；页面是操作工具（Operate），信息优先级是输入与动作、结果、档案管理。
- 单段单人音频的文件选择、麦克风录制及执行前试听。登记与查询均可引用已有声音，也可使用临时文件/录音；文件选择和临时录音本身不创建声音库素材。
- 登记时填写可选标签、可选绑定现有声音；登记成功后显示新档案。登记音频与绑定参考声音可以不同。
- 新音频识别与 matched / unknown / ambiguous、原因、原始分数、有限候选和实际使用的 T/M、特征版本呈现。
- 档案列表、显式刷新、确认删除、重启后的持久化一致性；展示标签、可区分重名档案的 ID、登记时间、绑定状态和公开版本信息。
- 独立的生成入口：操作者明确选择已绑定且可用的档案，输入目标正文，选择已有支持克隆的模型和其支持的生成设置，然后显式执行；成功后按既有生成结果体验试听/访问输出。
- 识别配置未准备、TTS 未准备、权限、无效音频、繁忙、取消、超时、保存/执行错误、已删档案及失效绑定的可恢复反馈。

范围外：

- 新建专用 App、第三方客户端、独立 Web 生产站点、Windows 实机验证、实时/流式识别、多说话人 diarization、转写、身份核验或防伪。
- 新模型训练、识别算法变化、阈值自动校准、在 UI 中调参、自动学习/合并档案、识别模型/TTS 模型自动下载或 GB 级 TTS 资产准备。
- 档案重命名、补录音、原位更换绑定及新的编辑协议。沿用 REQ-001：需要更换登记音频或绑定时显式删除旧档案，再登记新档案；不暗中用同名登记覆盖。
- 新的持久配置产品、云上传、用户素材自动采集、Git 推送、合入主线、签名发行、公证或二进制发布。

本次默认复用已准备的约 26.5 MB、本地 CPU 单线程识别资产与固定参数；这是主 Agent 提供的验证准备事实，不是本产品阶段新执行的模型结果。识别配置的连接方式、桌面调用契约、配置来源及验证工具由工程规划确定；不预先指定新的持久化配置实现。

## 术语、规则与不变量

| ID / 术语 | 含义与归属 |
|---|---|
| TERM-UI-01 声纹档案 / profileId | 独立登记的特征及公开元数据；不等于 voiceId、字幕角色或模型预置 speaker |
| TERM-UI-02 声音 / voiceId | 原声音库的 TTS 参考音频及参考原文，按原有声音库流程管理 |
| TERM-UI-03 临时输入 | 当前登记或查询选中的文件/录音；默认不写入 Voices，不作为查询历史长期保存 |
| TERM-UI-04 绑定 | 登记时显式关联已有 voiceId；只决定生成的参考音频/原文，不替用户决定目标正文或情绪 |
| TERM-UI-05 识别结果 | 模型当前分数规则下的 matched / unknown / ambiguous；错误不是 unknown，候选不是已选身份 |

1. **RULE-UI-01 输入有界**：沿用 REQ-001，文件不超过 20 MiB，解码时长 1–60 秒且支持既有解码类型。录音明确显示正在录制和计时，60 秒自动停止并告知；选入超过上限的文件不能静默截短接受。不保证自动识别所有噪声、音乐、多人或伪造素材。
2. **RULE-UI-02 临时素材与隐私**：选择文件、录音、试听及识别均不自动导入声音库。登记成功只新增档案及其私有特征；绑定引用已有声音。查询不修改档案、绑定或声音库；临时查询素材在服务操作终态清理，页面缓存的试听素材在更换/清除/离开后释放，不写持久状态。页面数据和 State 不携带向量，反馈不暴露内部路径、运行命令或 Token。
3. **RULE-UI-03 显式登记**：点击登记才创建档案，成功后才显示完成并刷新列表。可选标签省略时展示 ID；明确填写时沿用去空白后 1–100 个 Unicode 字符的规则，重名允许。同音频或同标签再次明确登记产生独立 ID；请求中或结果未知时不自动重试制造重复档案，应先刷新列表确认。
4. **RULE-UI-04 服务决定匹配**：原服务仍拥有识别决策。UI 原样表达 matched / unknown / ambiguous 和原因，不用显示舍入后的数值重算。matched 才有确定 profileId；unknown/ambiguous 可以显示候选但不显示已选身份。空库 unknown、无分数；低于 T 为 unknown，达到 T 但并列或分差小于 M 为 ambiguous，其余 matched。T/M 的精确边界继承 REQ-001；当前固定基线 T=0.6、M=0.05、识别超时 120 秒，不自动校准或改变。
5. **RULE-UI-05 公开信息与刷新**：列表和候选显示公开标签及可区分重名的 ID，候选按服务原始分数排序、上限沿用当前服务（至多 3 个）。列表加载失败不可展示为「无档案」；手动刷新可重新读取同一目录的最新档案。输入更换后先前结果须清除或明确标为先前输入结果，不能把旧结果视为新输入已识别。
6. **RULE-UI-06 删除与重启**：删除前展示将删除的档案并确认，取消确认不改数据。成功后档案不再列出、新查询/生成不可使用，重启不复活；重复删除保持已删除。已有声音、作品和生成历史不删除。失败保留原列表并允许重试/刷新。与删除重叠的识别可显示开始时完整快照，之后生成必须重新检查存在和绑定，不能仅信任旧结果。
7. **RULE-UI-07 生成必须由用户发起**：进入页面、登记成功或得到任何匹配结果均不生成。生成入口要求用户明确选定档案并点击执行，不把 matched 自动设为待执行选择；unknown/ambiguous 的第一候选不能自动生成。用户可在独立生成入口明确选择任一可用绑定档案，与查询结果是否 matched 无关。
8. **RULE-UI-08 绑定语义保持**：生成使用选中档案的绑定参考音频/保存原文；目标正文、模型与所支持的情绪/速度等设置仍由用户控制。无绑定、声音已删除、档案已删除、模型不支持克隆、缺必要参考原文或设置冲突时解释原因并拒绝，不回退到其他音色。没有 TTS 模型/运行时也不阻止档案登记和识别；生成禁用或返回明确的准备提示，并保留用户输入以便恢复。
9. **RULE-UI-09 操作终态准确**：登记/识别/生成处理期间显示当前动作及取消途径，防重复点击；已有昂贵操作繁忙时立即反馈，不增加无限排队或后台重试。沿用原取消/超时及登记原子提交语义：提交接受点前取消不迟到写入，接受点后已落盘成功须报告成功。失败不能保留本次旧成功结果；结果未知时引导刷新，而不武断显示取消成功或自动再登记。
10. **RULE-UI-10 配置与权限可恢复**：配置缺失/模型失败/特征版本不兼容均是错误，不伪装成 unknown。给出准备本地识别配置、重启并重试、换输入或重新登记等对应指引；不暴露路径/执行配置、不自动下载。列表/删除的可用性不依赖识别模型已准备。麦克风权限只在用户开始录音时请求；拒绝或设备缺失时说明恢复方式，并仍可选文件；停止/重录/离开页释放采集设备。
11. **RULE-UI-11 旧能力兼容**：原声音库、创作页、字幕、作品和生成参数语义保留。切换到声纹页不隐式保存/覆盖作品，也不把 profileId 写进旧的 voiceId、字幕 speakerId 或预置 speaker 字段。新入口继承原 App 的本地信任和服务授权边界。

## 体验和质量要求

- 页面标题和说明区分「声纹档案」与「参考声音」；首屏能确定输入用于登记还是查询。登记和识别为不同显式动作，档案列表以可扫描的行呈现，危险删除与主要提交动作不混淆。
- 每项操作覆盖初始、输入已准备、录音中、处理中、成功、正常拒绝、失败、取消和繁忙状态。列表有加载、空态、读取失败及重试；空态指导首次登记。完成反馈可由辅助技术读取，错误说明用户能做的下一步。
- 录音有明确开始/停止/重录、计时及试听；录音期间暂停冲突的音频播放，避免把 App 播放声意外录入。未经开始录音不请求麦克风权限。
- 生成表单展示选中档案及绑定声音、目标正文、模型和相关支持参数；绑定无效时明确标示，用户修正后可恢复。TTS 不可用时不阻断真实识别试用。
- 没有可绑定声音时仍允许登记未绑定档案，并指向原声音库的声音准备流程；不因打开绑定选择器而创建素材。需要将已登记档案换为新绑定时说明删除再登记的现有流程。
- 复用原设计系统的组件、语义颜色、间距及主题，不增加另一套 UI 框架。中英文同义，键盘焦点/可访问名称和对比度沿用现有规范；结果与错误不只依靠颜色识别。
- 适用设备为原 Mac App：至少在默认 1280×840 和最小 390×600 窗口检查关键动作，窄窗口可纵向排布/滚动、长标签/ID 可访问、侧栏折叠后仍可操作；不新增移动端产品承诺。
- 不增加实时性能承诺。界面在录音及模型运行期间能反馈进度并接受取消；识别执行时间有界。记录每条真实查询时延，若出现超时/卡死则按失败报告。持久化、并发、删除与取消耐久性沿用 REQ-001，不扩展断电或取证级擦除承诺。

## 验收证据边界

1. SCN-UI-01 至 SCN-UI-21 的产品行为由必要的确定性检查与桌面/页面旅程覆盖；模拟数据只证明 UI、参数及业务分支。
2. SCN-UI-22 必须走构建出的原 Mac App 与其本地服务。原 CLI/HTTP 证据只作依赖基线；浏览器预览、模拟后端或旧 App 不能作为当前页面真实识别通过的证据。若预览提供状态演示，必须明确标示不可执行真实识别，不能伪装推理成功。
3. 文件输入的真实识别验证、系统麦克风授权/真实采集、生成参数正确性与真实 TTS 听测独立记录。麦克风无法实际录制时列为未验证，不能以文件导入代替；不自动采集用户录音作为新质量样本。
4. 已准备且许可允许的 TTS 模型可验证实模生成，再由人工听测目标正文可懂、无明显截断/静音、无明显音色串换。没有模型时本次必须验证可恢复提示和禁用行为，真实音质继续标为未验证；不把假引擎音频或播放器可播放当作音质结论，不自动下载 TTS。
5. 每项证据绑定当前源码/App 构建、环境、固定配置及输入版本，保留实际命令/动作、结果和未执行项。工程规划选择具体 runner、构建/检查命令与保存位置，并满足项目 UI/核心/原生的适用检查；产品正文不把存在入口写成已通过。
