# REQ-003：声纹辅助音色查找与故事角色应用

## 问题、方向来源与目标

本地操作者已经有参考声音和角色预设，拿到另一段单人录音时，希望找到可复用的音色，再为明确的作品、角色或当前演绎选择参考声音。当前普通选择器按名称查找；声纹页面另有登记和识别操作，识别结果尚未接入普通选择回调。操作者仍需手动从档案绑定定位声音，并判断应用会影响哪个目标。这是本会话认可的使用方向，尚无市场、转化、查找耗时或人群准确率数据。

- 新方向来源：用户在本会话认可“融入声音选择/声音库”和“融入故事配音/角色预设”后，请求形成实施方案。长期目标/产品文档来源：`none`；不推导新的商业承诺。
- 依赖事实：`.sdlc-v1/project.md`、`REQ-002.product.md` 与当前源码。采集分支 `codex/speaker-validation-ui`，HEAD `822c0a4b7b0465e5f70a0331bb396e2fedadd901`，含尚未验收的 FEAT-002 未提交 WIP。
- 目标：录音查询提供可试听的已有参考声音；操作者确认目标及应用范围后，复用普通声音选择和草稿保存链路。匹配只帮助查找，不能代替目标选择或真实身份判定。
- 本阶段只交付产品正文。下文“拟新增”均未实现/体验验证；现有源码入口也不等于 FEAT-002 已正式验收或发布。本轮不运行模型/App，不实现、提交或推送源码。

## 两条主旅程与准备流程

**旅程一：查找已有参考声音。** 在主参考声音选择器或声音库点击“按录音查找音色” → 选择文件/开始录音 → 停止、试听 → 显式查询 → 查看 matched/unknown/ambiguous。matched 显示档案标签及 ID、绑定声音及可区分的 ID，用户试听绑定 Voice 并确认。选择器通过原选择回调返回 Voice；声音库只定位/试听已有声音，不修改隐藏的当前草稿。普通按名称查找、导入、录音保存继续是独立动作。

**旅程二：为明确目标选择参考声音。** 从故事当前角色/台词的主参考入口，或库角色当前默认设置/演绎的编辑入口打开同一选择能力 → 查询并试听 → 确认作品、目标角色/演绎及影响范围 → 只应用 Voice。角色候选仅辅助定位：从识别档案的绑定声音找出当前作品角色和库角色/演绎中引用同一声音的项；零个候选不阻止为已明确目标选择 Voice，多个候选须人工区分。候选不自动认定录音属于某角色、不分配台词，也不复制候选的模型、情绪或速度。

**准备流程：先有声音，再显式登记。** 需要新增素材时走原声音库导入/录音保存流程。对于已保存 Voice，可点击“登记声纹”，展示将用作登记样本及绑定目标的当前 Voice，提供试听和可选档案标签；操作者确认后登记，成功刷新档案状态。失败保留已保存 Voice。其他登记样本、未绑定档案或删除管理使用现有声纹页面；换绑定仍沿用显式删除后重新登记，不承诺原位编辑。

建议按两批交付；这是验收边界，不是工程 Task 拆分：

| 批次 | 有界成果 | 可观察验收条件 |
|---|---|---|
| A：共享查找与声音库准备 | 共享查询能力，先接入文本主参考选择和声音库查找；已有 Voice 的登记便利入口 | matched 有效绑定经试听/确认返回正确 Voice；声音库查询只定位；查询不增加 Voice/档案/生成任务；登记成功只增加绑定当前 Voice 的档案，失败不撤销 Voice；未知、歧义、失效、取消和识别不可用均能恢复普通选择。覆盖 SCN-INT-01 至 13 |

## 范围、实体与业务规则

范围内为原 Mac App 的主参考声音选择、声音库查询/登记，以及故事和角色预设编辑接入；页面沿用本地资料、播放器、选择器、临时采集和保存链路。情绪参考入口保留原选择语义，首期不接入声纹查找。查询入口默认关闭，由用户显式打开；不将普通导入改为自动识别。

范围外：多人自动分离/转写、整段视频自动分角色、实时识别、唱声音色控制、身份核验、防伪、上传自动去重、未匹配自动登记、自动生成、新识别算法/训练/阈值或 256 维特征变化、数据库、角色迁移、新公共 CLI/v1、档案原位换绑、模型自动下载、Windows 实机或独立 Web 站点发行。

| 实体 | 所有者与关系 |
|---|---|
| Voice / voiceId | 声音库中的原始 TTS 参考音频和 referenceText，由原声音库管理；可被多个档案/角色引用 |
| SpeakerProfile / profileId | 私有声纹档案及公开元数据；bindVoiceId 是操作者选定的 TTS 映射，允许未绑定，不表示真实身份或角色的一一对应 |
| Character / characterId | 库中的角色预设，持有默认 SynthesisSettings 和演绎；其名称不作为身份键 |
| CharacterPerformance | 角色演绎的独立设置快照；句子或草稿保存的快照可以与库中版本不同，按其所属目标区分 |
| SubtitleSpeaker / speakerId | 某作品中的项目角色；settings/characterId 是项目自己的引用及快照，不等于 profileId |
| 临时查询与派生候选 | 仅当前交互中的输入、结果和当前数据派生项；不进入旧 State/作品格式，不持久保存 profile 引用 |

1. **RULE-INT-01 显式、只读查询。** 文件/录音查询不导入 Voice、不登记档案、不修改绑定、不选择目标或发起生成。沿用单人 1–60 秒、20 MiB 输入约束，录音 60 秒自动停止；越界或无效输入明确报错，不静默裁剪文件。识别服务拥有 matched/unknown/ambiguous 决策及有限候选；保持已有 T/M、超时与特征版本，不根据显示舍入值重算，不将相似度描述为概率/准确率。
2. **RULE-INT-02 绑定定位。** 只有 matched 且可读取的档案与有效 bindVoiceId 才提供绑定 Voice 的确认动作。unknown/ambiguous 不把第一候选当成已选声音；用户可换输入或返回普通声音选择。无绑定、档案已删或 Voice 已删显示各自原因，并引导现有档案管理/声音准备；不按标签猜测、不回退其他声音。
3. **RULE-INT-03 确认与有效性。** 确认前用现有公开列表及当前 State 刷新档案/绑定/声音，并按 ID 解析；读取失败不能当作空库成功，也不能沿用未经确认的旧绑定。两个读取不组成跨实体原子事务。若已观测到绑定变化，刷新展示并重新确认。确认后的内容是普通 Voice 引用：后来删除 profile 不撤销已确认声音/作品；Voice 后续删除沿用原缺失提示和生成校验，不自动替换。
4. **RULE-INT-04 只应用主参考。** 选择 Voice 对业务设置只修改明确目标的主参考 voiceId/referenceText；不替换目标正文、情绪参考/情绪、速度、模型、模式或其他角色，不设置 characterId，不清除演绎，不自动保存库角色或启动生成。后续保存/生成沿用原流程和模型能力校验，自动保存更新 updatedAt 等元数据仍按旧语义，不计为业务设置误覆盖；不以 speaker.generate 白名单限制该选择能力。
5. **RULE-INT-05 范围尊重快照。** 故事当前句有独立 performance 时，更新只作用于该句快照；否则更新当前角色默认设置，使用该默认设置的台词随之变化，已有独立演绎保持。确认前说明“当前句演绎”或“该角色默认参考（独立演绎保持）”，并展示受影响目标；首期不提供覆盖全部句子演绎的音色动作。角色编辑器只改当前默认设置或所选演绎，原保存/放弃机制继续负责持久化。
6. **RULE-INT-06 派生候选无身份结论。** 按绑定 voiceId 与现有角色/演绎的主参考比较；项目角色按项目当前设置和原有回退规则解析，句子快照按自身设置，不用库角色旧值代替项目快照。候选展示所属作品/库角色、角色/演绎名及可区分 ID；同一 Voice 可对应零个或多个项。用户可用候选定位并打开原目标编辑入口，再确认参考选择；不能因名字相同自动应用。整个 Character 预设的原有应用操作另行明确选择，其复制设置/清除演绎的旧行为不混入查找确认。
7. **RULE-INT-07 迟到结果与取消。** 输入更换、关闭、目标/作品/当前句或所选演绎变化后，旧结果不得写入新上下文；已展示的确认状态必须失效。只对本次 requestId 请求取消，反馈区分“取消请求已发送”“已取消”“取消未确认/结果未知”，不取消其他生成。正常取消、超时或失败不沿用本次旧成功结果。登记请求未知时先刷新档案，不自动重试；真实落盘成功按现有提交语义报告。
8. **RULE-INT-08 生成与互斥。** 普通生成无需先识别；默认选择/生成链路不新增识别步骤或模型准备要求。用户显式发起 identify/enroll 才占用现有昂贵操作，识别与 TTS 不要求并行；已有操作繁忙立即反馈，无无限排队/后台重试。识别中的编辑、反馈和取消可响应；用户返回普通选择可继续，昂贵生成等待当前操作终态或按旧繁忙语义拒绝。
9. **RULE-INT-09 独立登记。** 声音库便利入口使用当前 Voice 作为登记源并显式绑定它；标签沿用已有规则，重名和重复明确登记产生独立 ID。只在成功后刷新完成状态；服务提交前复核发现 Voice 已删除时拒绝登记，不创建替代绑定。档案已提交后再删除 Voice，仍按已完成登记报告，绑定缺失通过刷新或后续使用反馈，不把已落盘成功改为失败。失败不删除/回滚 Voice、作品或原档案；需要再次登记由用户显式发起。

## 体验、性能与隐私约束

- **Surface 方向：Operate。** 原声音选择/库/故事编辑的身份与 Astryx 组件/token 优先。仅借用 Impeccable 的任务、信息架构和状态方法，不执行完整 critique、context launcher 或新增设计引擎。选择器内以显式子区域逐步展开查询；主次顺序为目标与作用范围 → 输入/试听/查找 → 结果/绑定试听 → 确认。查询录音按钮与“保存到声音库”明确区分。
- **状态完整。** 包含未开启、准备输入、请求权限、录音中/计时、可试听、查询中/取消、matched 可用/未绑定/失效、unknown、ambiguous、配置不可用、繁忙、错误、超时、取消未确认。档案加载、空库和读取失败分开；成功状态不代表已应用。登记入口另有确认、处理中、成功、失败/结果未知及刷新恢复。
- **恢复与键盘。** Tab 可达文件/录音/试听/查找/取消/确认/返回；图标有可访问名称、焦点可见，结果/错误用文本与辅助技术反馈，不只靠颜色。关闭返回入口焦点，重试保留可修正输入；清除、更换或关闭释放临时资源。录音开始时暂停冲突播放；取消/等待反馈不遮住恢复控件。
- **窗口与语言。** 沿用原 Mac App 默认 1280×840、最小 390×600 的约束；窄窗口纵向排布/滚动。长作品名、角色名和 ID 可完整访问，关键动作不溢出；中英文语义、明暗主题一致，不新增移动产品承诺。
- **性能与可靠性。** 默认选择和生成不等待识别配置/请求。查询不新增实时性能承诺，沿用已有有界超时；记录实际查询耗时与超时/取消结果。请求中界面可响应编辑/取消，重复点击不启动重复任务；沿用昂贵操作互斥，不承诺识别和 TTS 同时推理。取消未确认时保留准确反馈，终态/刷新后再发起新请求，不自动排队。
- **隐私与权限。** 麦克风仅在用户开始录音时请求。音频本地处理；服务临时输入在操作终态清理，页面 Blob/试听 URL 在换输入/清除/关闭时释放，不写持久查询历史、普通 State 或声音库。公开结果不含 embedding、内部存储/执行路径或 Token；档案特征仍由私有存储负责，保存/删除继承 REQ-002。仅继承本地操作者权限，不增加账号/认证，不将绑定或标签表述为真实身份。观察记录默认只含脱敏计数、状态、耗时和目标范围，不自动收集音频。
